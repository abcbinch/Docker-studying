# Docker 사용법

<h4>사용</h4>
<ul>
  <li>서버: node.js 18</li>
<li>Docker(orbStack): 28.5</li>
<li></li>
</ul>


<h4>Dockerfile 작성</h4>
<ul>
  <li>FROM node:18</li>
  <sub>*어떤 베이스(환경)에서 서버를 만들고 실행할지 결정합니다.[^1]*</sub>
  <li>WORKDIR /app</li>
  <sub>컨테이너 내부의 작업 디렉토리입니다.[^2]</sub>
  <li>COPY package*.json ./</li>
  <sub>package.json 파일을 먼저 복사해서 app 폴더(디렉토리)에 저장합니다.[^3][^4][^5]</sub>
  <li>RUN npm install</li>
  <sub>npm install을 실행합니다.[^6][^7]</sub>
  <li>COPY . .</li>
  <sub>로컬 폴더의 코드를 컨테이너 디렉토리(폴더)로 복사합니다.[^8][^9]</sub>
  <li>EXPOSE 8080</li>
  <sub>설정한 컨테이너 주소를 작성합니다.[^10]</sub>
  <li>CMD ["node", "server.js"]</li>
  <sub>node로 서버 코드가 들어있는 파일(server.js)를 실행합니다.[^11][^12][^13]</sub>
</ul>

<details>
  <summary>덤</summary>

    [^1]: FROM은 필수요소입니다. 없으면 작동하지 않습니다.
    [^2]: WORKDIR는 준필수요소입니다. 설정하지 않으면 서버 파일들이 컨테이너의 기본 시스템 파일들과 뒤섞여 저장됩니다.
    [^3]: *은 와일드카드 기호입니다. package와 .json 사이에 무슨 단어/글자가 들어가든 복사합니다. ex)package-lock.json
    [^4]: 필자는 node.js를 설치하지 않고 package.json을 직접 작성한 다음 실행했습니다.
    [^5]: RUN을 하기 위해서 package.json을 먼저 복사해야 합니다.
    [^6]: package.json에 어떤 내용이 있느냐에 따라서 설치 내용이 달라집니다.
    [^7]: 필자는 node.js를 사용했기 때문에 npm을 실행했지만, 어떤 서버를 만드느냐에 따라서 내용은 달라집니다.
    [^8]: '.'와 './'는 로컬 폴더의 경우 
    [^9}: '.'와 './'는 똑같습니다. 둘 다 '현재 작업 중인 폴더'를 가리킵니다. 그러나 '디렉토리'라는 것을 더 직관적으로 보여주고 싶을 때 './'를 사용합니다.
    [^10]: 컨테이너 내부 주소이자, 서버 코드에서 설정한 주소이기도 합니다. 포트 매핑 시 오른쪽에 작성합니다.
    [^11]: 해당 형식은 Exec 형식으로, 배열 안에 문자열을 넣는 방식으로 실행합니다. 중간에 다른 디렉토리를 거치지 않고 직접 실행하기 때문에 안정적입니다.
    [^12]: 서버 코드 파일의 이름에 따라서 달라집니다.
    [^13]: FROM을 제외한 나머지는 필수요소가 아닙니다. 그러나 없으면 불편해질 수 있는
 
</details>
